# 발견: 변환공간의 45°는 물리적 45°가 아니다 (funnel 모순의 해명)

## 증상

같은 funnel(팁 아래 원뿔, R=14, h=5, 벽 오버행 70.3°)에 대해 두 방법이 정반대 결론:

| 방법 | outward 원뿔 판정 |
|---|---|
| 변환 방식 (메시 왜곡 후 45° 판정) | 44°까지도 서포트 53% — "outward 소용없음" → 셀렉터가 inward 선택 |
| 해석식 (국소 빌드방향 투영, 팀메 방식) | **26°에서 서포트 0%** — "outward로 완전 해결" |

## 원인 (둘 다 손계산으로 재현됨 — 구현 버그 아님)

- **물리적 진실**: outward 원뿔 레이어의 국소 빌드방향은 `sinθ·r̂ + cosθ·ẑ`.
  면-빌드방향 각도가 곧 해석식 `g(θ) = n_z·cosθ + n_r·sinθ`. 축대칭이면
  **유효 오버행 = 원래 오버행 − θ** 로 정확히 빠진다: 70.3−26 = 44.3 ≤ 45 → 통과.
  (RotBot 논문의 "바깥 오버행엔 outward" 규칙과 일치.)
- **변환공간의 함정**: 원뿔 변환은 XY를 1/cosθ 배로 **늘리는 비등각(anisotropic)
  사상**이라 각도를 보존하지 않는다. 벽의 warped 기울기는
  `m = h·cosθ/R + sinθ` 가 되어, funnel 벽은 **53°가 되어야** warped 공간에서
  45°를 통과한다. 즉 warped 공간의 45° 판정은 물리적으로 **과도하게 엄격**
  (바깥보기 벽 기준)하다.

## 시사점

1. **이전 발견 정정**: "구→outward, funnel→inward" 중 **funnel→inward는
   왜곡된 지표의 인공물**이었다. 물리적으로는 funnel도 outward가 정답.
   (방향이 형상 의존이라는 명제 자체는 유효 — 안쪽을 보는 오버행(그릇 안쪽 등)은
   여전히 inward가 맞다. 예시를 교체해야 함.)
2. **파이프라인 실전 문제**: 변환된 메시를 일반 슬라이서에 넣고 **기본 45°
   서포트 임계**를 쓰면, 물리적으로 필요 없는 곳에 서포트를 깐다(또는 반대).
   → 슬라이서 자동 서포트를 끄고 해석식 판정으로 서포트를 지정하거나,
   슬라이서 임계각을 왜곡을 반영해 조정해야 한다(엄밀히는 위치 의존).
3. **기준 확정**: 물리 판정(서포트 필요 여부)의 **표준은 해석식**(`conical/analytic.py`,
   팀메 방식)으로 한다. 변환 방식은 "왜곡 공간에서 슬라이서가 보는 것"의
   시뮬레이션으로만 유지.

## 재현

```
python3 - <<'EOF'
# docs 수치 재현: 두 관점의 통과 각도 (26° vs 53°)
import numpy as np
R,h=14.,5.
print('유효 오버행 = 70.3 - theta -> 45 이하가 되는 theta =', round(70.3-45,1))
for th in (26,44,53):
    m=h*np.cos(np.radians(th))/R+np.sin(np.radians(th))
    print(th,'deg: warped 오버행', round(90-np.degrees(np.arctan(m)),1))
EOF
```
